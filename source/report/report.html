THE ENGINE BEHIND THE FACE2026.11
01 · 这是什么 / 为谁而做

一座会“醒”的网站 WHAT & FOR WHOM

《机心》不是在页面里嵌一个 3D 小窗，而是整个页面就是一个可以走近、可以动手的空间。

设定（虚构）

雾港城地下的第九井里，封存着一台曾经替城市说话的心智——傀-7。它的脸是一张烧出来的白瓷面壳，裂纹用金补过。夜班技工在它脚下摆了一只改装成散热器的青铜炉。访客扮演的，就是今晚值班的那个人。

为谁而做

  • 喜欢科幻叙事和网页 3D 的玩家：不需要安装，打开链接就能玩，鼠标、触屏、键盘都能完成整个流程。
  • 评委与路过的人：30 秒内看到招牌变形；愿意多留一会儿，就能钻进引擎里看簧片和字鼓。
  • 创作者同行：演示“少量 AI 生成的主角资产 + 代码构建的世界”这条工作流能做到什么质感。

想让人记住的一件事

“它不是在计算，它是在给自己唱。”——心智被具象成一台八音盒：四只字鼓，每只八个字，铜针拨动簧片；它的每个念头都是四个字，一共 4096 种。

画面里所有文字、读数与“念头”都是设计内容，不是真实的智能或遥测数据；网站内已明确标注“虚构设定”。

02 · 创意从哪里来

“有机械者必有机事，有机事者必有机心” CONCEPT

“机心”出自《庄子·天地》。两千多年前这个词是贬义：用了机械，人就会生出机巧之心。我们把它反过来读——如果机械自己长出了一颗心，它会是什么样子？

方向取舍（只比较了三个，没有做大范围调研）

方向为什么选 / 不选
瓷面 + 八音盒心智（采用）有一个天然的“招牌动作”——把脸打开；机械八音盒让“思考”变成看得见的齿、针、簧片，近景经得起看；人脸这种有机雕塑正好交给 Lux3D。
织机心智（经纬线织出记忆）画面新鲜，但大量细线在实时渲染里容易闪烁，交互因果不如“开脸”直接。
记忆星盘（环套环的浑天仪）容易滑向“发光球 + 粒子”的通用科幻观感，辨识度不够。

刻意避开的东西

  • 发光的大脑、霓虹球、粒子场、堆满图表的科幻仪表盘。
  • 围着一个 3D 小部件写长篇功能介绍的营销页。

参考视频给我们的启发

参考视频（一个剖开头部、内部是房间的 3D 网页）让我们确认了两点：空间要分层，信息面板要贴着场景出现。我们没有照搬它的构图与题材：《机心》的头是合着的，要靠访客自己打开；里面不是房间，是一台机器。

机心 JIXIN · 项目报告书04
04 · 招牌变形

把脸打开：雨停了一拍 SIGNATURE TRANSFORMATION

同一个动作改变的东西

  • 主体：一张脸变成两个侧脸 + 一台机器。
  • 天气：雨停住、微微上浮；水面的雨圈消失。
  • 城市：亮窗波、招牌增亮、空中交通放慢。
  • 光与色：冷青 → 暖金，雾色、调色、辉光同步过渡。

为什么可信

  • 两半面壳各由两根会伸缩的液压杆托着，杆端始终贴在面壳内壁上（加载时对生成网格做射线求交得到锚点）。
  • 切口处内衬向外翻卷，与釉面闭合，没有“纸片边”。
  • 面壳背面是黑漆与金线电路，不是空的反面。

运动的层级

  • 大：面壳开合、三环转动。
  • 中：字鼓步进（带回弹的机械卡位）、莲瓣、灯奴巡逻。
  • 小：簧片衰减振动、存储单元闪烁、线缆上的光包、封条摆动、香烟。

所有运动都由状态驱动，没有“只是在转”的装饰。

机心 JIXIN · 项目报告书07
07 · Lux3D 的作用（二）

生成的是“主角”，代码让它“会动” GENERATED × CODED

为什么把这三件交给 Lux3D

脸、青铜器、带磨损的小机器——这类有机造型与手工质感是程序化几何最不擅长、而图生 3D 最出效果的地方。它们也是画面里观众视线停留最久的三样东西：主角、近景道具、中景的“活物”。

明确的分工

来自 Lux3D 生成来自代码 编写
头部、铜炉、无人机的几何缩放与摆位；头部的分片、枢轴与开合动画
三件的基础色 / 粗糙度贴图内衬、缝光、开片细纹；把贴图里的金缮线识别出来并在苏醒时点亮
概念设定图（文生图）无人机琥珀玻璃的内发光、巡逻与转头；铜炉旁的供品与香烟

如实说明：场景中其余全部内容——引擎、光环、井体、城市、雨、水面、线缆、封条、界面、声音——都不是 Lux3D 生成的，而是程序化几何、自写着色器和代码动画。我们没有为了“用得多”而把每个面都拿去生成。

10 · 技术实现

一个静态网站，两种时钟 ARCHITECTURE

网站本体

  • 纯静态：HTML + ES 模块 + 3 个 GLB，无构建步骤、无后端、客户端没有任何密钥；任何静态托管都能直接部署。
  • three.js r180（固定版本，随包分发），WebGL2。
  • 约 2,000 行自写代码：engine / halo / mask / world / materials / textures / post / director / ui / audio / main。
  • 加载进度、WebGL2 不可用、上下文丢失、模型缺失都有可用提示。

画质档位（如实标注）

档位内部分辨率MSAA其它
原生 FIDELITY100%（原生）4×全部
均衡 BALANCED75%2×反射减半
流畅 PERFORMANCE50%无无阴影 / 反射
自动 AUTO50–100% 动态2×按帧率调节

界面左下角始终显示真实的内部渲染分辨率；低于 100% 的档位明确标为放大输出，不计作原生。

同一个场景，两种推进方式

  • 实时：requestAnimationFrame 驱动，时间步随刷新率变化。
  • 离线录制：?capture 关闭 rAF，由录制器每次推进精确的 1/120 秒并渲染一帧。所有动画只依赖仿真时间与固定种子，结果可重复。

导览 = 调用公开动作

自动导览与母版用的是同一份脚本：它只接管相机，其余全部通过访客也在用的动作完成——alignRing()、wake()、stepDrum()、检视卡片。所以视频里发生的每件事，在网站里都能亲手做到。

4K120 母版的录制方法

  • 无头 Edge，视口 3840×2160、DPR 1，逐帧校验绘图缓冲与场景目标尺寸。
  • 每帧：推进 1/120 s → 原生渲染 → 经 DevTools 协议无损 PNG 截图（含界面）→ 管道送入 ffmpeg。
  • 无放大、无插帧、无重复帧；分 6 段录制后无损拼接。
  • 声音：记录仿真中每次发声调用的帧号，再用网站同一合成器在离线音频上下文里重放，混入时视频流逐字节不变。

针对性的优化

  • 重复物体全部实例化：井墩 12、楼体 560、机柜灯 7,560、雨 26,000、封条、簧片、招牌等。
  • 静态结构合并为少量网格；整场约 180 次绘制调用。
  • 细节尽量进着色器而不是贴图：拼板缝、窗格、电路、洗墙光都随距离淡出以避免闪烁。
  • 只有 1 盏投影灯；井壁上百处“灯”是画在材质里的。
  • 渲染目标内存（估算）：原生 4K 约 485 MB，其中 4×MSAA 的 HDR 颜色与深度占大头——这是高画质档最贵的部分，其余档位据此降级。

先量再改

录制前对单帧成本做了拆分计时（timing.mjs）：4K 原生渲染约 40 ms，无损截图约 0.68 s——瓶颈在截图而不是渲染，于是没有去动画质。

素材与许可

没有使用第三方模型、贴图、字体文件或音频采样。文字用访客系统自带的中文字体绘制；招牌、封条、读数均为原创虚构内容。three.js 许可证随包附带。

诚实的局限

  • 中文书法字体取决于访客系统（楷体 / 宋体回退），不同设备上字形略有差异。
  • 生成模型的贴图为 2048²；极近处的清晰度靠代码细纹补足，面壳背面与内衬的五官处有少量内缩自交。
  • 水面反射、4×MSAA 在原生 4K 下开销大，集显设备请用“均衡 / 流畅”。
  • 视频里的声音由网站同一套合成器离线生成并按仿真帧对齐；录屏本身不采集浏览器声音。
  • 触屏流程可用，但界面主要按桌面横屏设计。
  • 实时 4K/120 尚未在 120Hz 设备上验证，见上一页。
